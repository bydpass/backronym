# 词库审核目录（v00.03.00 第 3 批）

每门语言一个子目录：`fr/`、`de/`、`es/`、`it/`、`la/`。流程：

1. 第 2 批的词库管线（`npm run lexicon`）把候选表写到这里。
2. 第 3 批先由 DSH（Sonnet 5.5）普查（T17），再由 Codex 6.1 Sol 复审（T18），结果都写回这里。
3. 主会话合并、重新生成词库（T19）。

> **接手前先读 [HANDOFF.md](HANDOFF.md)**：那是 T18 开始时的历史交接；最新状态见项目根目录 HANDOFF.md（当前复验见 q4-rereview-20261110/REPORT.md）（状态、已验事实、已知坑、操作纪律、成本参考），本文件只写规格与流程。

- 本目录不进打包（在 `app/` 之外）。
- 进 git 的：`report.json`（覆盖报告）、`dsh-NNN.tsv` / `codex-NNN.tsv`（修订与结论）、本说明。
- 不进 git 的（`.gitignore`）：`candidates.tsv`（整表，**始终是合并审核之前的内容**，审核文件的键以它为准）、`merged.tsv`（合并后的逐条结果，供查看）、`shard-NNN.tsv`（分片原表）。
- 抽检比例与通过线见 `plans/v00.03.00/PLAN.md` 的 Q4。

## 分片

`shard-NNN.tsv`：表头加上最多 300 行，按频次从高到低排，所以 001 是最常用的词。分片数量：fr 69、de 48、es 77、it 89、la 26，共 309 片。

**普查期间不要重跑 `npm run lexicon`**：重跑后分片的内容和编号会变。修订是按「词 + 显示 + 词性」合并的，不会丢，但分片编号就对不上了。

| 列 | 含义 |
|---|---|
| 词 | 小写原形 |
| 显示 | 卡上显示的写法（德语名词首字母大写；拉丁语带长音，例如 amō） |
| 词性 | noun / verb / adj / adv / pron / prep / conj / det / article / intj / num / particle / contraction |
| 性别 | m / f / n / mf（阴阳两可）/ mn / fn / person（男女同形的人称名词）；复数专用的带 `\|pl` |
| 冠词 | 规则生成；空 = 不显示 |
| 冠词判定 | `known`，或 `unknown:<原因>`（未知的不猜，确认后才写） |
| 判定来源 | tags+head / categories（法语 h）/ ipa / spell / letter_name |
| 英文释义 | 维基词典（kaikki）前 4 个义项 |
| 中文释义 | 自动生成；全角逗号分隔，最多 4 个，每个不超过 10 个字 |
| 释义来源 | cfdict / handedict（直接反查）、en（经英语、按 ECDICT 机械映射）；空 = 没有中文 |
| 标记 | 待普查（没有中文）、冠词待审、长音待审（拉丁语）、不雅候选（kaikki 标签）、LDNOOBW待判 |
| 得分 | 频次得分（拉丁语为名次） |

## T17 普查（DSH）

**输入**：`<语种>/shard-NNN.tsv`。

**输出**：同目录的 `dsh-NNN.tsv`，编号与分片相同。制表符分隔，表头：

```
词	显示	词性	字段	原值	新值	理由
```

- 每处修改写一行；一个词条改了几个字段，就写几行。
- 「字段」可取：中文释义 / 词性 / 性别 / 冠词 / 标记 / 显示。
- 没问题的行不写。只修不增：不新增词条，不删词条。
- 「词」「显示」「词性」照抄分片里的原值，合并时就是按这三列找词条的。
- 「词性」字段被改时，新值写在「新值」列，前三列仍照抄原值。

**给普查员的说明**（试点用的就是这段，可以直接照搬；把 `<语种>` 和 `NNN` 换成实际值）：

> 你是「藏头 - Backronym」词库审核链的普查员（T17）。只用中文写理由。审 `review/lexicon/<语种>/shard-NNN.tsv`（表头 + 最多 300 行，按频次从高到低）。这些条目是程序自动生成的：英文释义来自维基词典，中文释义由直接反查或「英文释义 → ECDICT 第一个义项」机械映射得到，所以常有错义、偏字、词性串用；冠词由规则生成。
>
> 逐行核对：
> 1. 中文释义是不是这个词在该词性下最常用、最准确的意思（参照英文释义和你对该语言的了解）。错义、偏字、只剩虚字（如单独一个「的」）、把别的词性的意思串过来的，都要修。中文义项用全角逗号分隔，最多 4 个，每个不超过 10 个字；形容词带「的」。
> 2. 词性、性别是否正确。
> 3. 冠词：
>    - 法语：le / la / l’（元音或哑音 h 前）/ les（复数专用）/ le / la（两性）。
>    - 德语：der / die / das。
>    - 西语：el / la；首音节重读的纯阴性名词用 el（el agua），男女同形的人称名词指女性时用 la（la árabe）。
>    - 意语：il / lo / la / l’；s+辅音、z、gn、ps、pn、x、i+元音前用 lo。
>    - 拉丁语不写冠词。
>
>    带「冠词待审」标记的必须给出判定；没把握就在新值写「存疑」。
> 4. 不雅、侮辱、色情词在标记里写「不雅」，不要删；只是有一个俚语义项的常用词（如 bon、venir）不标。
> 5. 带「待普查」标记的（没有中文）要补上中文。
> 6. 古旧词、存疑词在标记里写「古旧词」或「存疑」。
>
> 只修不增：不新增、不删词条，没问题的行不写。输出写到 `review/lexicon/<语种>/dsh-NNN.tsv`，制表符分隔，表头 `词	显示	词性	字段	原值	新值	理由`。「词」「显示」「词性」照抄分片原值；「字段」可取 中文释义 / 词性 / 性别 / 冠词 / 标记 / 显示。只写这一个文件，不改其他文件，不运行 git。最后回报：审了多少行、各字段修改了多少处、最常见的错误、没把握的条目。

**试点**（11-09，Sonnet 5.5，法语 001 片，300 行）：
- 改了 142 个词条，共 184 处：中文释义 173（其中补待普查 11）、标记 9、性别 2；结果在 `fr/dsh-001.tsv`，**还没经 Codex 复审**。
- 主会话抽查了 22 处，都合理。
- 成本约 15 万 token，耗时约 2.4 小时。

## T18 复审（Codex）

**输入**：`dsh-NNN.tsv`，加上同一分片 `shard-NNN.tsv` 里没被修改的行（抽查用）。

**输出**：`codex-NNN.tsv`，表头：

```
词	显示	词性	字段	结论	建议值	理由
```

- 「结论」只取 通过 / 驳回 / 存疑。
- DSH 的每处修订都要有一行结论。
- 抽查的未修订行，有问题才写（结论填「驳回」、建议值填正确的值）。
- 驳回 DSH 修订时，建议值写正确的值；觉得原值就对，就把原值抄进建议值。

**给复审员的说明**（可以直接照搬）：

> 你是「藏头 - Backronym」词库审核链的复审员（T18）。只用中文写理由。读 `review/lexicon/<语种>/dsh-NNN.tsv`（普查员对 `shard-NNN.tsv` 的修订），逐条判断修订是否正确：通过 / 驳回（给出建议值）/ 存疑。再从 `shard-NNN.tsv` 里随机抽至少 30 条普查员没改的行复核，有问题的也写进来（结论「驳回」，建议值给正确的值）。标准与普查员相同（中文释义取该词性下最常用、准确的义项，全角逗号分隔、最多 4 个、每个不超过 10 个字；冠词规则见 `review/lexicon/README.md`）。输出写到 `review/lexicon/<语种>/codex-NNN.tsv`，制表符分隔，表头 `词	显示	词性	字段	结论	建议值	理由`；「词」「显示」「词性」照抄原值。只写这一个文件，不改其他文件，不运行 git。最后回报：通过 / 驳回 / 存疑各多少，抽查了多少条、发现几处问题。

## 交回后的检查与合并（主会话）

```bash
npm run lexicon:check            # 检查所有 dsh / codex 文件：表头、字段名、结论取值、引用的词条在不在候选表里、有没有漏判
npm run lexicon                  # 重新生成词库；自动应用已复审的修订，report.json 里记应用了多少
```

合并规则（T19，`scripts/build-lexicon.mjs` 读本目录）：
- Codex「通过」的 DSH 修订：照新值写入。
- 「驳回」：写入建议值。
- 「存疑」：不写入，登记到 AUDIT。
- 只有 DSH、还没有 Codex 结论的分片：**不写入**。
- 改了中文释义的条目，自动去掉「待普查」标记。
- 只改性别（含 `|pl`）：冠词按审核后的性别与单复数重新判。
- 最终词性不是名词：性别、冠词自动清空，不必逐字段写。
- 性别 / 冠词要清空时写「（清除）」（例如只用于无冠词短语的名词）。
- 标记写「存疑：中古词」的归古旧词，留在词库；其余含「存疑」的排除出词库。

之后按 Q4，每门语言随机抽 200 条做验收（错误率 ≤ 3% 算通过），主会话再抽 30 条独立复看。

### 主会话审核步骤（Astra 二轮交回后）

```bash
npm run lexicon:check                      # ① 格式
npm run lexicon:audit -- --samples         # ② 统计与规则核对 → <语种>/audit.json；抽样表 sample-q4.tsv（200）、sample-main.tsv（30）
npm run lexicon                            # ③ T19 合并、重新生成词库（R2 剩余路径修好之后再跑）
npm run lexicon:audit -- --after-build     # ④ 逐条核对 words.js 实际写入的值是否等于预期最终值
```

- ② 只读：不改分片、普查与复审结果、词库。规则核对的是合并后的预期最终值（只核会进词库的条目），检查项为：
  - 释义格式：全角逗号、1–4 个义项、每个不超过 10 字、含汉字、不夹外文残片；
  - 词性、性别、冠词的取值；
  - 冠词与「复审后的性别和单复数」是否一致（按规则显式重算）。
- 抽样用固定种子，同一份输入每次抽到同一批：
  - `sample-q4.tsv`：每门语言 200 条，交外部按 Q4 验收，错误率 ≤ 3% 算通过；
  - `sample-main.tsv`：30 条，修订过、没修订过的各 15 条，由主会话独立复看。
  - 两张表的最后两列「判定」「错在哪」留给审核人填写。
- ④ 报四类问题：该进词库却没进、释义没写进去、冠词不对、标了存疑或不雅却还在词库里。
