# 设计记录

## 界面改动先在设计系统里敲定（2026-11-08 用户定）

设计系统 Artifact「藏头 - Backronym」<https://claude.ai/artifact/RozXkcF9R3FjEiBqo2T8HG> 是界面的唯一敲定处。

项目门户（G8）另用一套：Artifact「藏头 - Backronym 门户」<https://claude.ai/artifact/UzRtpUeYL4aubPpv2ZE5LT>（2026-11-22 用户定）。门户的界面在那一套里敲定，产品这一套不管门户；下面的更新办法两套相同，「实现后的核对」只针对产品这一套。

- 颜色、字号、间距、组件、文案、交互的任何改动，先改它：`tokens.json`、`README.md`（总则）、`components/<组件>/` 的说明与预览。用户确认后才改 `app/`。
- 还没确认的方案做成一张方案稿卡片，并在总则「已定、未实现」一节登记。确认并实现后把登记划掉，方案稿移到 `archived/components/`。
- 每批界面实现收尾时，回设计系统把对应的「未实现」划掉。
- 怎么更新：按该 Artifact 类型的说明，只写 `project/` 下的文件，索引 `design-system.json` 最后发。

## 实现后的核对

- 令牌与 `style.css` 的变量、`core.js` 的色板（`PALETTES`）同值。
- `components/bundle.css` 第二段与 `style.css` 逐字一致。第二段从 `style.css` 的「*, *::before」一行起算，前面的字体声明与主题变量不在同步段里。
- `components/bundle.js` 开头一段与 `app/assets/i18n.js` 逐字一致（界面文案表，v00.04.00 批 0 起），紧接着的一段与 `core.js` 逐字一致。`core.js` 的字到文案表里取，两段要一起同步。
- 从运行中的产品截取的组件预览，产品改了要重新截取，做法见 [commands.md](commands.md)「设计系统预览的重做」。

## 现行设计

- **母版**：满版 folio × 国际主义 × 左对齐，以第六稿 `design/folio-swiss.html` 为准；交互以当前应用源码为准（2026-11-24 用户定）；`design/v00.02.01-gate-a.html` 是 v00.02.01 的定稿，留作记录。各轮的关口与批准记录在 `design/DESIGN_CONTROL.md`。
- **版式**（2026-11-20 用户确认，v00.03.03）：卡面怎么排跟着作品走，两个预设（对开是默认，居中）加十个开关，在编辑面提示行的「版式」页里选。界面本身仍一律左对齐。
- **主题**（2026-11-11 用户批准；2026-11-20 加「表格」）：fandom（默认，只有浅色）、单色画、印象派、分离派、表格（只有深色），加深浅三档（跟随系统 / 浅 / 深）。由 `app/assets/theme.js` 切换，颜色在 `style.css` 的 `:root[data-skin]`，导出色板在 `core.js` 的 `PALETTES`；深色档的卡和导出图也是深色。各主题的色值、字体与出处见设计系统的「四个主题」一节。
- **已退场**：早期的「石白 / 墨 / 朱」（用户 11-18 重申）只作主题脚本没跑时的回落色，产品里选不到；设计稿与预览不要再拿它当现行配色。
- **标准**：参照 W3C 的 WCAG 2.2（界面本身）与 ATAG 2.0（藏头是创作工具，还要帮作者做出看得清的图）；设计稿逐帧注明条款（2026-11-04 用户指定）。
- 改视觉前读 `design/TASK_BRIEF.md`，先看它文件头的「现行核对」。
