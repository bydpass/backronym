# 架构要点

> **四个主题（2026-11-12，颜色部分）**：`<html data-skin>` 定主题（fandom 默认且只有浅色、dansaekhwa 单色画、impressionism 印象派、secession 分离派），`data-theme` 仍定深浅，都由 `theme.js` 在页面画出来之前写好并存在设备上（`backronym-skin`、`acronym-meme-theme`）。颜色在 `style.css` 的 `:root[data-skin]`，卡与导出图的色板在 `core.js` 的 `PALETTES`，经 `CORE.paletteOf(主题, 是否深色)` 取（`app-view.js` 的 `currentPalette`）；两处同值与对比度由 `test-core.mjs` 核对。只有浅色的主题选着时 `theme.js` 固定写 `data-theme="light"`。`:root` 里的石白 / 墨和 `CORE.PALETTE` 只作主题脚本没跑时的回退。**主题字体**（2026-11-12）：`core.js` 的 `SKIN_FONTS` 定每个主题的西文、中文字体，`CORE.useSkinFont(主题)` 换卡与导出共用的字体串（`CORE.FONT` 是取值器，跟着变）；`app-view.js` 的 `applySkinFont` 在启动和换主题时调用，字体到位后作废基线实测并重画，`ensureFonts` 导出前等当前主题的字体。样式里用 `--font-latin` / `--font-cjk`。字体文件由 `scripts/build-fonts.mjs` 生成（可变字体拆成固定字重；Libre Baskerville、Federo 是保留字体名，裁剪版改名为 BK Fandom Serif、BK Secession Display）；原始文件在 `scripts/.cache/fonts/`，缺了就只重出 Noto。

> **语言多选（2026-11-12）**：作品可以同时选几门语言，一律平等。`state.langs` = 选中的语言（按语言栏的顺序），`state.lang` = 定字母规则的那一门（五门西文同一套规则，所以只要选了西文就按西文，只选英语才按英语），`state.pickLangs[i]` = 第 i 格的词来自哪门语言。`CORE.useLangs(codes)` 设选中的语言：数字格读法、屏蔽词表、预设词按它们合起来算；`CORE.withLang(code, fn)` / `app.model.inLang(code, fn)` 临时按某一门取数据（候选、查词、断词表）。候选栏逐门取词后轮流排，条目来自哪门用 `app.model.tagLang` / `itemLang` 记在内存里。草稿：选了不止一门才写 `langs` 与 `pickLangs`，`lang` 仍写定规则的那一门；旧稿读作只选了 `lang` 一门。每门语言各用一个加载器（`loaderOf`）。加减语言都不清空内容；只在「取消后只剩英语而单词或某格的词英语规则放不下」时拦下（`app-entry.js` 的 `englishOnlyBlock`）。卡上冠词的对齐按冠词本身判断（der / die / das 左对齐，其余右对齐）。

> **T19 接入（2026-11-11，交付54）**：六语 `words.js` 改由 `scripts/t19/build-packs.mjs` 从已复审的新范围词库生成，旧管线成品不再随包。每个词包有两部分：`words`（旧四列格式，只含可默认推荐的义项，候选与随机用）和 `lexicon`（全部准入义项、每义项词形，以及人名的性别与来源语言 `names`，手动查词用）。查词经 `lexicon-policy.js` / `lexicon-store.js`（`fromPack`、`packLookup`），在 `core.js` 之后加载；英语的 `lexicon` 是全局 `LEXICON_EN`。下文关于词库生成脚本、短语补充表与变形索引 forms 的描述是旧管线的，旧查词路径只在词包没有 `lexicon` 时才走。详见[交付54报告](../../review/t19-batches/t19-batch54-20261111/REPORT.md)。

6. 应用模块按 `model → title → media → view → editor → entry → publish → draft` 加载（文件名为 `app-<模块>.js`），最后 `app.js` 绑定事件和启动。沿用 ES2017 经典脚本，无框架、转译或依赖。职责见下表。

| 文件 | 职责与状态归属 |
|---|---|
| `app-model.js` | 唯一的 `state` / `el`、公共编辑与弹层辅助函数 |
| `app-title.js` | 富文本、快照、选区、标题输入法状态、键盘工具栏 |
| `app-media.js` | 图片选择、异步加载序号、取景交互与预览 |
| `app-view.js` | DOM 卡、Canvas 绘制、字宽测量、画布缓存、外壳与滑动 |
| `app-editor.js` | 单格输入、候选与义项栏、输入法和焦点状态 |
| `app-entry.js` | 入场输入、预设、改单词确认 |
| `app-publish.js` | 端能力访问、完成面板、导出、保存与发布 |
| `app-draft.js` | 草稿控制器：保存队列、恢复、覆盖保护、到期调度；存储引擎仍是 `draft.js` |
| `app.js` | 事件绑定与启动 |

`app-model.js` 创建临时 `window.Backronym`；各模块闭包持有同一个上下文，通过 `app.<模块>.<接口>` 调用。跨模块可变字段只由所属模块持有，`state` / `el` 共享同一对象；缓存、计时器和存储闸门留在所属闭包。`app.js` 启动后删除该全局入口，不新增长期调试接口。注册阶段不调用尚未加载的模块；`app-draft.js` 初始化存储控制器需要 `app-publish.js` 的 `miniTool`，不得交换二者加载顺序。

测试加载器 `scripts/app-source.mjs` 从 HTML 读取真实模块顺序，用 JS 解析器确认函数边界；定点测试注入替身，另有真实模块注册/接口完整性断言与浏览器回归，避免只测替身漏掉接线错误。字体生成脚本扫描全部 `app*.js`，新增模块无需另加扫描清单。

几个跨文件才看得出的约定：

- **在图上编辑**：编辑面是一张 DOM 卡（单图每次渲染当前格，列阵渲染全部格），看到的就是成品；Canvas 只负责导出。两者的坐标、字号、折行、截断都来自 `CORE.layoutCard` / `layoutGrid` 返回的框列表（1080 坐标；文字宽度由 app-view.js 注入的 `measure()` 测量）：DOM 卡按框摆放（`renderDom`），导出按框画（`paintBoxes`），不各自排版。改版式只改 `core.js` 一处，之后跑 `scripts/check-dom-layout.js` 和 `scripts/export-hash.js` 对照。
- **入场界面**（v00.02.01 / T18）：没有有效草稿时先到 `#entry`（单词 `#wordInput`、6 个随机预设 `CORE.pickPresets`、填表人 `#fillerCtl`、「开始填充」）；有草稿直接进编辑界面（`focusEntry` 在读完草稿后路由），18h 清理后回入场界面。编辑界面提示行右侧「改单词 / 填表人」（`#toEntry`）回到入场界面（改词页）。改词页（第七批 T30）顶栏「返回｜保存｜主题」：保存走同一套校验，`app.draft.persistNow()` 等这一版真正写进本设备后留在本页、Toast「已保存」，失败或原稿保护阻塞时变「重试保存」并页内说明；返回时无修改直接回，有待应用或未写入的修改（`app.draft.unsavedNow()`）从返回按钮向下展开 `#leavePop`（保存并返回 / 放弃修改 / 继续编辑）；改词页回车 = 保存并返回。输入只暂存在入场页，`submitEntry` / `validateEntry` 统一校验（空单词、屏蔽词就地说明、不复述原词），会清空已有内容的格时先弹 `#wordConfirm`（初始焦点在「保留原单词」），通过后 `applyEntry` 一次性 `setLetters`（`keepSame`）、给字母变了的格递增配图序号并保存。填表人只在入场界面改，卡上只显示（镜像画出）。读草稿期间 `#wordInput` 禁用，预设与主按钮的点击由捕获阶段守卫拦下。
- **选词流程**：单词在入场界面输入（只收 A–Z 与 0–9、≤14 个；数字格的词以读法首字母或该数字开头都算对，见 `CORE.cellInitial` / `startText`），生成的格子是空的，由用户在卡上给每格打一个以该字母开头的词（v00.02.01 / T17 起只认首字母：`containsLetter` 就是首字母相等，候选只来自词首档，朱红关键字母恒为词首，`state.keys` 恒为 0、仅为草稿格式保留，圆圈点选高亮整套已删），每次给 8 个、可点「下一批」翻页（第七批 T39 由「换一批」改名）、可点「随机一个」。中文查询按义项命中排序（完全命中 > 部分命中 > 模糊，同档保持词频，T06）；`CORE.candidates` 还整理首屏（T25）：先剔除屏蔽词，再按命中档（英文前缀 > 义项完全命中 > 部分命中 > 模糊）从高到低填，不跨档换位；档内首轮同词族最多 2 个、形容词在族内最前、副词和第二个近义形容词推迟，首轮挑完还有空位就按该档原序补回（含副词），所以有 8 个可见词首屏就是满的；精确输入的词固定第一位。没有“试试：”建议词，首字母不对时只提示“不是以 X 开头”。「随机一个」的池排除人名 / 姓氏 / 地名词条（T07，只动随机池，候选与搜索照旧）。首屏之后的屏蔽词不在 `CORE.candidates` 里全量过（单字母查询两千多条），仍在 `app-editor.js` 取页（`pageOf` 的 `skip`）与 `randomOne` 里过。不要改回“输入单词后自动给每格配词”或长列表。
- **标题**：卡顶标题框只有标题一种模式（T18 起删除了「首次」「改单词」模式与 `titleMode()`）；标题留空时导出用单词本身（`CORE.titleOrWord`），发布笔记标题同理。键盘上方一行只在焦点在标题框时出现，出现时 `placeKbRow` 给页面底部留出「这一行 + 软键盘」的空白（T08）。
- **画图 / 导出**：两种视图——列阵（全部格子 1 张）和单图（每个字母 1 张 1080×1440），默认单图。导出入口是顶部栏「完成」→ `onFinish()` 先查每格合法（词以该字母开头）和屏蔽词，通过后弹完成面板，`exportAll()` 逐张绘制、逐张释放画布，防低端机 OOM。浏览器里没有端能力时，面板里的「导出图片」列出图，长按或右键另存。
- **深浅两套色板与深色导出**：卡和导出图都跟随深浅档位（深色档导出深色图）；点「完成」那一刻取一次 `THEME.isDark()`，整批用同一套色板。CSS 变量与 `CORE.PALETTE` 手工保持同值。
- **端能力**：一律经 `miniTool(name)` 访问 `window.xhs.miniTool`，不存在时返回 null 并降级（浏览器里保存/发布不可用，提示右键另存）。端能力调用用 `within()` 加超时，防界面卡死。
- **草稿**（v00.02.01 / T23 起）：主键 `backronym-draft-v2`，同时写 `setStorage` 和 `localStorage`，读取取较新的一份。旧版两个键 `acronym-draft-v1`、`acronym-draft-v1-bak` **只删不读**：`draft.js` 的 `purge` 每次清理时无条件定向删除，删除失败由 `cleanupFailed` 机制重试，不碰其它键。`CORE.migrateDraft` 只做字段合法性校验（要求 `v: 2`，没有就是坏数据；`keys` 恒为 0），不再转换旧格式。恢复副本键 `backronym-draft-v2-rescue`（两侧都写）存**原文字符串的 JSON 数组，最多 3 份**（`RESCUE_MAX`），同字节去重，每份按自身 `t` + 18h 到期；`preserve` 逐侧「读 → 合并 → 写 → 读回确认含这一份」，读不到某侧现有副本就不写那一侧，已满 3 份未到期就算保全失败、不挤掉任何一份。读到新版原文却套用到界面时出错（或原文结构不能用）时，`app-draft.js` 的 `draftGuard` 闸门在**第一次覆盖主键前**调 `draftStore.preserve(raw)` 把原始字节存进副本、逐侧读回比对，至少一侧一致才放行；两侧都失败就不覆盖、编辑只留内存、底部写明。读取抛错（没拿到原文）时闸门先 `recheck()` 重读主键：读到原文走保全，确认为空或过期才放行，仍失败不写。读到了稿、但主键有一侧读失败（如本地旧 LIFE 可读、端上较新的 LOVE 读不到）时，`read()` 的 `failed` 记下是哪一侧，`app-draft.js` 的 `sideGuard` 让那一侧在核实前不写（`draftStore.write(payload, skip)`，另一侧照常写）；`sideCheck` 用 `recheck(sides)` 只重读那一侧，读到的每份未到期原文（与恢复稿同字节的除外，`sideKeep`）先 `preserve` 再放行并补写，仍读失败或保全失败就继续不覆盖、底部写明。**先保全**：两侧都读到、但某一侧主键存着与恢复稿字节不同的未到期原文时（如跨会话：本地较新的 LIVE、端上较旧的 LOVE），`read()` 的 `differ` 记下那一侧，同样挂 `sideGuard`（`sideRead` 为假，提示不说「读取失败」），覆盖前先把它存进副本。副本从不续期；`read()` 把主键和副本数组里的每一份（两侧）一起比较，取有效且最新；清理逐份剔除到期项，数组空了删键。`readDraft` 先迁移验证再比时间（不合法的一份不能淘汰完整草稿）；读完前 `#wordInput` 与「完成」是禁用的，恢复本身只重绘、不写盘、不刷新时间戳。连续18h无内容更新保存则到期，清当前作品/主稿/副本；无旧稿宽限。底部显示规则、真实保存状态与到期时间。详见 `docs/draft-expiry-assessment.md`。
