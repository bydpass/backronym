# 架构要点

**许可与借物页（T07，2026-11-12）**：代码 GPL-3.0-or-later，五门西文词库 CC BY-SA 4.0，`design/`、`docs/` CC BY-NC-SA 4.0，做出的图的版式部分 CC BY 4.0。借物页从上到下是本项目许可段、省流三行、十五行来源表、六项许可全文。全文的来源是仓库根目录 `LICENSES/*.txt`，`scripts/build-licenses.mjs` 由它生成两份随包的载体：`app/LICENSES/*.html` 是独立文件，只进外链网页版（`build-web.mjs` 检查）；小红书的 zip 打包时排除它，因为容器不收 `.txt`，且整个包只许根目录一个 `index.html`（2026-11-14 真机预览两次被拒后定，`npm run pack` 末尾由 `scripts/check-zip.mjs` 检查）。借物页因此不说「包内有」，只说全文也在源代码仓库的 `LICENSES/` 目录；GPL 与三份 CC 许可另生成 `app/assets/licenses.js`，借物页里对应的 `<details data-license>` 展开时才插 `<script>` 读它（`app.js`，与语言包同一种读法）；MIT 与 OFL 带版权人声明，直接写在 `index.html`，与根目录 `LICENSES/` 下的同名文件同文。`test-app.mjs` 还按容器的文件类型白名单检查 `app/`。省流三行与 README「许可」一节是同一段文字。以上几处一致性都在 `test-app.mjs` 里比对。

> **四个主题（2026-11-12，颜色部分）**：`<html data-skin>` 定主题（fandom 默认且只有浅色、dansaekhwa 单色画、impressionism 印象派、secession 分离派），`data-theme` 仍定深浅，都由 `theme.js` 在页面画出来之前写好并存在设备上（`backronym-skin`、`acronym-meme-theme`）。颜色在 `style.css` 的 `:root[data-skin]`，卡与导出图的色板在 `core.js` 的 `PALETTES`，经 `CORE.paletteOf(主题, 是否深色)` 取（`app-view.js` 的 `currentPalette`）；两处同值与对比度由 `test-core.mjs` 核对。只有浅色的主题选着时 `theme.js` 固定写 `data-theme="light"`。`:root` 里的石白 / 墨和 `CORE.PALETTE` 只作主题脚本没跑时的回退。**主题字体**（2026-11-12）：`core.js` 的 `SKIN_FONTS` 定每个主题的西文、中文字体，`CORE.useSkinFont(主题)` 换卡与导出共用的字体串（`CORE.FONT` 是取值器，跟着变）；`app-view.js` 的 `applySkinFont` 在启动和换主题时调用，字体到位后作废基线实测并重画，`ensureFonts` 导出前等当前主题的字体。样式里用 `--font-latin` / `--font-cjk`。字体文件由 `scripts/build-fonts.mjs` 生成（可变字体拆成固定字重；Libre Baskerville、Federo 是保留字体名，裁剪版改名为 BK Fandom Serif、BK Secession Display）；原始文件在 `scripts/.cache/fonts/`，缺了就只重出 Noto。

> **真机反馈后的界面改动（2026-11-17）**：① 配文可折行：`CORE.wrapCaption(measure, text, dy)` 按字贪心折行（西文单词尽量不拆），字号 48、行距 62，末行基线不超过 `CARD.CAPTION.last`，所以词没折行时 3 行、词每多折一行少一行；`layoutCard` 为每行出一个 `caption` 框（带 `line`）。`#capCtl` 是透明的多行 `<textarea>`（`placeCaption`：行高 = 版式行距，高度够放这格最多的行数），叠在镜像上，编辑时镜像实时折行；回车收键盘，粘贴的换行换成空格。textarea 不默认继承字体，`style.css` 里和 input 写在同一条 `font-family: inherit`，否则西文的折行与光标全错；镜像没有避头尾，浏览器有，标点落在折行处时框里可能比镜像多一行，框不许上卷（`scroll` 时归零），否则各行都和镜像错开一行。再打就排不下的那次输入不收（`onLineCtl`，同单词框的 R9；末尾的空格按「后面还能不能再放一个字」算，否则写满后还能一直打进看不见的空格）。组字期间三个卡上输入框都保持透明，镜像按框里正在组的字先画（`app.editor.composePreview` → `layoutData`，不写数据）：安卓带候选的输入法打西文全程在组字，以前改由输入框自己显示，真机上选定候选前卡上一片空白。单词框组字期间候选栏只留提示行（`renderComposeBar`：格首提示与计数器 `#candCount`，按框里正在打的字计、超上限先写明），候选列表与按钮收起，上屏后恢复（v00.03.01 E6）。② 信息行（页码、填表人）字号 34；填表人上限 `CORE.FILLER_MAX` = 16，信息行放不下时截断。③ 统一提示 `showToast` 的位置固定在顶栏正下方，不再跟标题走；设置页 / 借物页开着时不弹，先记下、页面关掉后 `flushToast` 补弹，打开页面时收起正在显示的那条；某条提醒过时了用 `dropToast(msg)` 收回（连同暂存的，例如设置页里切浅色再切回深色，标题颜色提醒不该在关页时补弹）；保存到相册、发布笔记的结果也走它（读屏另写常驻的 `#live`）。④ 入场页全数字不再写读法；语言摘要选了多门只写首字（`aria-hidden`），全名写在旁边的 `.sr-only` 里给读屏。⑤ 深浅三档的选中样式是 2px 墨框 + 勾 + 粗体，不靠反色。

> **语言多选（2026-11-12）**：作品可以同时选几门语言，一律平等。`state.langs` = 选中的语言（按语言栏的顺序），`state.lang` = 定字母规则的那一门（五门西文同一套规则，所以只要选了西文就按西文，只选英语才按英语），`state.pickLangs[i]` = 第 i 格的词来自哪门语言。`CORE.useLangs(codes)` 设选中的语言：数字格读法、屏蔽词表、预设词按它们合起来算；`CORE.withLang(code, fn)` / `app.model.inLang(code, fn)` 临时按某一门取数据（候选、查词、断词表）。候选栏逐门取词后轮流排，条目来自哪门用 `app.model.tagLang` / `itemLang` 记在内存里。草稿：选了不止一门才写 `langs` 与 `pickLangs`，`lang` 仍写定规则的那一门；旧稿读作只选了 `lang` 一门。每门语言各用一个加载器（`loaderOf`）。加减语言都不清空内容，也不拦：v00.03.01 E2 起英语格内上限也是 28，六门规则收的字一样（原来只剩英语时超过 20 字的词会被 `englishOnlyBlock` 拦下，已删）。卡上冠词的对齐按冠词本身判断（der / die / das 左对齐，其余右对齐）。 **核对已有词条时不跨语言顶替（V003-B4-R11，11-13）**：`itemFor` 带着原条目和格号调用（恢复草稿、`refreshPicks`）时，这一格记着的语言还选着但词库没到，就原样留着不查，等它到了再核；否则英语等先到的语言里的同形词会顶替它并清掉冠词。没记语言的格、记着的语言里查不到的格同理（V003-B4-R12）：要到别的语言里认，就等选中的语言全部到齐，再按语言栏的先后找；在自己记着的语言里查得到的不用等。去掉一门语言时（`toggleOne`）要立刻 `refreshPicks`，否则等着它的格在本次会话里不会再被核对。

> **词库重建（2026-11-19）**：每语 `words.js` 包含候选与义项（v00.03.04 起不带词形门控 `formGate`）；`inflections.js` 提供义项级词形及名词性数，由 `app-model.js` 的 `warmForms` 在语言就绪后预读：等页面 `load`、再让出 1 秒、再等浏览器空闲才发请求（`load` 之前插脚本会拖住 `load` 事件；紧跟着挂载会拖慢到可用）。预读没到时打字，`formStatus` 直接去读；页面还没 `load` 完时（恢复草稿就会查词）只登记、不发请求。词形表读失败的语言不再挡着别的语言认词；但这只对没记语言的格成立——记着语言的格在它的词形表读失败期间原样留着，不到别的语言里认（复审 G-A2：法语 ira 是 aller 的变形，法语词形表失败时只查得到意语名词 Ira，会把已选的词条顶替掉）；到达的回调读成功、读失败都重核各格的词（复审 G-A1：只在成功时重核的话，最后到的那门若失败，旧稿里等着认的词就一直不补）。主编辑器通过 `formStatus` 区分加载中、失败、确无结果。旧稿自动释义和词性选择在 `itemFor` 与 `refreshPicks` 重对。生成契约见 [词库范围](../lexicon-scope.md)。下方 T19 和旧管线记录说明历史格式。
> **短 ID（v00.03.02 批 S1，2026-11-20）**：词包里的义项 ID 是 3 位 base36 短 ID（原哈希在六语全部义项里统一排序后的名次，先后同原哈希），`inflections.js` 每行行首是义项在 `lexicon.senses` 里的下标。原哈希只在生成侧（编译包、补登记文件、审核表）。要把两者对上用 `scripts/t19/build-packs.mjs` 的 `shortIds()`。草稿不存义项 ID，不受影响。
> **词形拆干（批 S2，2026-11-20）**：`inflections.js` 里词形多的行写成「词干 + 词尾串下标」，词尾串在 `tails` 里去重。读词形行一律用 `LEXICON_STORE.rowForms(sidecar, row)`，不要自己 `split`。
> **反查表现建（批 S3，2026-11-20）**：词包不带中文反查表 `reverse`。`core.js` 的 `reverseOf(pack)` 在第一次中文反查时由义项的中文栏现建，并记在词包对象上。键的先后跟义项先后走，改义项排序会连带改变同分候选的先后。

> **漏音符查询（R3-12，2026-11-19）**：五语共用。`lexicon-store.js` 的 `packLookups` 以 `completion` 模式查：精确词头 → 精确词形 → 漏音符候选（组上标 `leak`，条目显示带音符的拼写与释义）。只允许补上缺失的音符，输入里已有的音符必须原样保留（`onlyAddsMarks`；publicó 不补成 público，farò 不反向给 faro）；防误借清单、逐义词形排除、只供精确查询、屏蔽器照旧生效（sur 不借 sûr）。`app-model.js` 的 `lexiconHit` 自动带出：有精确命中取第一个；没有时只有一个合格候选才带出，多个保留原输入由用户在候选栏点选；草稿重对时按已存释义认回原来的义项，词形索引迟到不顶替。`lookupAll` 把各语言的精确结果排在漏音符候选前，`lookupHit` 同理（这一格记着的语言先整门查）。前缀候选 `core.js` 的 `filterTiers` 也在输入带音符时要求候选同位置带同样音符；没打音符的输入仍去音符比。

> **T19 接入（2026-11-11，交付54）**：六语 `words.js` 改由 `scripts/t19/build-packs.mjs` 从已复审的新范围词库生成，旧管线成品不再随包。每个词包有两部分：`words`（旧四列格式，只含可默认推荐的义项，候选与随机用）和 `lexicon`（全部准入义项、每义项词形，以及人名的性别与来源语言 `names`，手动查词用）。查词经 `lexicon-policy.js` / `lexicon-store.js`（`fromPack`、`packLookup`），在 `core.js` 之后加载；英语的 `lexicon` 是全局 `LEXICON_EN`。下文关于词库生成脚本、短语补充表与变形索引 forms 的描述是旧管线的，旧查词路径只在词包没有 `lexicon` 时才走。详见[交付54报告](../../review/t19-batches/reports/t19-batch54-20261111.md)。

| `app-editor.js` | 单格输入、候选与义项栏、输入法和焦点状态 |

| `app.js` | 事件绑定与启动 |

`app-model.js` 创建临时 `window.Backronym`；各模块闭包持有同一个上下文，通过 `app.<模块>.<接口>` 调用。跨模块可变字段只由所属模块持有，`state` / `el` 共享同一对象；缓存、计时器和存储闸门留在所属闭包。`app.js` 启动后删除该全局入口，不新增长期调试接口。注册阶段不调用尚未加载的模块；`app-draft.js` 初始化存储控制器需要 `app-publish.js` 的 `miniTool`，不得交换二者加载顺序。

测试加载器 `scripts/app-source.mjs` 从 HTML 读取真实模块顺序，用 JS 解析器确认函数边界；定点测试注入替身，另有真实模块注册/接口完整性断言与浏览器回归，避免只测替身漏掉接线错误。字体生成脚本扫描全部 `app*.js`，新增模块无需另加扫描清单。

几个跨文件才看得出的约定：

- **界面文案**（v00.04.00 批 0）：界面上的字集中在 `app/assets/i18n.js`，代码里只写编号，经 `I18N.t("编号", { 占位: 值 })` 取；各模块顶上的 `STR` 就是它。一句话一条，会变的部分写成 `{名字}` 占位，不在代码里拼句子。排在 `core.js` 之前加载。`core.js` 与 `lexicon-store.js` 用到时才取（自检常单独装它们），`CORE.BLOCKED_MSG`、`CORE.SKINS` 因此是读的时候才算的属性；`theme.js` 在文案表之前加载，`THEME.LABEL` 存的是编号，由 `app.js` 取字。`index.html` 的静态文字仍留中文，元素上标 `data-i18n`（元素里唯一一段字）、`data-i18n-html`（夹着别的标签的整段）、`data-i18n-attrs="属性:编号;…"`，表里 `h.` 开头的条目与它逐字相同，`scripts/test-i18n.mjs` 看住两边一致、编号没有漏用错用、脚本里没有散落的中文；许可本体里的版权行标 `data-i18n-skip`。表里有中文、英文两列（批 1），英文的编号、占位、标签与中文逐条对应，`[[一个时|其余]]` 按 `{n}` 取单复数。**界面语言**在 `i18n.js` 载入时定：设置页选的（`localStorage` 的 `backronym-ui-lang`，只存本机）优先，否则跟随 `navigator.language`——中文环境用中文，其余用英文，读不到用中文；容器给不给 app 语言还没真机核实。不是中文时 `I18N.apply` 把页面上带编号的静态文字换掉，并改 `<html lang>`（英文界面的样式靠 `:root[lang="en"]` 认）。各模块在加载时就取好的常量不会跟着变，所以设置页换语言先经 `persistForReload` 确认图片和当前草稿均已落盘，再存语言偏好并重载。写入失败或超时保留当前页面和内容。释义之间的「，」是词库数据自己的写法，不换；读屏说明里的顿号、逗号、分号走 `sep.*`。没进表的：`pre.lang = "zh-CN"`、量字体用的探针字。文案表的注释也会被字体脚本扫到，别写界面上没有的字。
- **英文释义**（v00.04.00 批 2）：义项在数据与草稿里一律以中文认（`state.glosses` 存卡面上的字，义项身份仍是「词性组 + 中文义项」）。英文只在显示时换：五门外语词包的 `lexicon.en` 与 `senses` 逐行对齐（0 / 原文 / `[原文, 短写]`，由 `review/en-gloss/<语言>.tsv` 经 `npm run en-gloss` 与 `npm run packs` 生成），`lexicon-store.fromPack` 挂到 `record.en`；`app.model.enGloss` 按条目写法重查，再按词性组和义项 ID 取英文，筛选后的候选须唯一对上词性和释义。英语的词与找不到的给空。`CORE.glossText` 是钩子：英文界面装 `enGloss`（`defaultGloss`、候选栏、义项栏、入场页都经它取字），中文界面不装、原样是中文；两种界面都装「另一种写法」，`savedAutoGloss` 恢复草稿时识别中英两种写法的自动释义，等对应主词包到齐才改写成当前界面的。义项栏按钮显示完整原文、点了填短写，亮起按短写比。词包 `more` 的第五列是类别代码 `pro` / `hist`，字到文案表取。预设表每行 `[词, 中文, 英文]`，英语预设没有英文。
- **冠词另选**（v00.04.00）：`state.artOwn[i]` 是用户另选的冠词，只能是这门语言的定冠词单数（用户定，不让自己写）。表在各语言规则文件的 `articles` 里，经 `CORE.articlesOf(语言)` 取；英语、拉丁语为空，所以没有这一行。另选了就盖过词库给的和 `state.arts[i]` 选的（`articleText`、`cellState` 经 `ownArticle` 先看它；不在表里的值不认，选中非名词义项时不显示已另选的冠词）。在义项栏的冠词一行里是按钮：词库给的在前，其余的在后。换词即清，随草稿存在 `artOwn` 字段，没另选就不写。不必二选一的那一行不带 `sense-row` 类。单独抽出 `cellState`、`articleText` 跑的自检要一并抽 `ownArticle`。
- **在图上编辑**：编辑面是一张 DOM 卡（单图每次渲染当前格，列阵渲染全部格），看到的就是成品；Canvas 只负责导出。两者的坐标、字号、折行、截断都来自 `CORE.layoutCard` / `layoutGrid` 返回的框列表（1080 坐标；文字宽度由 app-view.js 注入的 `measure()` 测量）：DOM 卡按框摆放（`renderDom`），导出按框画（`paintBoxes`），不各自排版。改版式只改 `core.js` 一处，之后跑 `scripts/check-dom-layout.js` 和 `scripts/export-hash.js` 对照。
- **版式参数**（v00.03.03 L1）：`layoutCard` / `layoutGrid` 从 `data.layout` 读一份版式，由 `CORE.layoutOf` 补齐成十项：`text`（词与释义的位置）、`cap`（配文的位置）、`title`（单图标题的位置）、`ratio`（图版比例，高度不变只收宽度）、`plateX`（图版左右）、`order`（图在上或在下）、`prog`（格子进度）、`filler`（填表人）、`deco`（墨线与墨条）、`quote`（配文引号）。预设在 `CORE.LAYOUTS`（`folio` 对开、`center` 居中）；不传、缺项、认不得的值都落回「对开」：改版前唯一的排法，只是格子进度默认不画（v00.03.03 真机反馈 F4，`LAYOUTS.folio.prog` 是 `false`；没存版式的旧草稿打开后也跟着变）。填表人只画名字，不带「填表人」三个字（F13）。对齐只改框的 `x`（框仍是 `align: "left"`），隐去就是不出那个框，引号直接写进配文的框，**绘制代码（`paintBoxes`、`renderDom`、`domBox`）不用认识版式**。隐去的元素留白不重排；只有 `order` 会把图版挪到 `CARD.FLIP.plateY`、文字整体上移 `CARD.FLIP.dy`。列阵只认 `text`、`title`、`prog`、`filler`、`deco`：不满的一行、每格的词与释义跟 `text` 走，顶上的标题跟 `title` 走（F8；`title` 只有左与居中，所以列阵标题不会靠右，「居中」预设的列阵标题在左边）。
- **版式的界面与草稿**（v00.03.03 L2）：版式存在 `state.layout`（上面十项加 `base` = 最后选的预设名，只给版式页看），`app-view.js` 的 `layoutData` 把它放进 `data.layout`，所以编辑面、导出、版式页的小样用的是同一份。草稿字段 `layout`：和「对开」不一样才写（`CORE.sameLayout`，不比 `base`），没动过版式的作品与旧稿打开后内容不变；`migrateDraft` 遇到这个字段逐项规整，缺项、坏值落回「对开」。清空作品（`clearDraftView`）回到「对开」。版式页在 `app-layout.js`：提示行「版式」进，全屏页，顶上钉住当前格的小样（用导出的同一套画法按小尺寸画）与两个预设，小样下面一对「单图｜列阵」只换小样（`prevGrid`，开页时跟编辑面的视图一致，不改 `state.view`）；下面「自定义」三组开关由 `GROUPS` 表生成；预设下面那行会变的说明只留给读屏（`#layBaseWhy` 是 `.sr-only`：显示出来的话一变页面就下移）；预设用 `click` 不用 `change`，已选中的再点一次也生效（恢复成预设）；键盘在已选中的预设上按空格或回车时浏览器不给 `click`，另由 `keydown` 补上。版式页是这份作品的：作品被清掉时（`clearDraftView`，如草稿到期）由 `app.layout.dismiss()` 收起，不像设置页、借物页那样留着。`trapKeys` 的首尾若是单选，取它那一组里选中的那个（Tab 只停在选中的单选上）。卡上的输入框跟着版式：释义框、配文框仍占满内容宽，字在框里按同样方式对齐（`text-align`）；词的输入框对准镜像里的词；词下面各行的下移量按词的行数算（不再从墨条反推，线饰可以隐去）；图版上的透明按钮跟着图版的框；标题框按 `title` 对齐。改单词时，默认图的取景不跟字母走：新出现的格、字母变了的格沿用默认图原来的取景（`setLetters`）；词下方的候选栏、义项栏跟着「图在下」的上移量走。取景面板的取景框也是这份作品单图的图版（`app-media.js` 的 `cropFrame`：高 600，宽随 `ratio`），预览框、拖动边界与卡面、导出取的是同一块；取景数据是相对值，换比例不用迁移。**配文引号**：排版和配文框的限长都经 `CORE.captionText` 取同一份字；开了引号时，写配文期间由配文框自己显示（`.own`），镜像先藏起来。
- **只有一套的主题**（v00.03.03 L3）：`theme.js` 的 `SKINS[x].only` 是 `"light"`（fandom）或 `"dark"`（表格），选着它时固定写 `data-theme`，设置页深浅那一组停用并按 `THEME.only()` 写原因。色板里只有那一套：`PALETTES.table` 只有 `dark`，`paletteOf` 两种情况都给它；`style.css` 里只有不带 `data-theme` 的一块。表格另有 `frame` / `giant` 两个色键（`--frame` / `--giant`）：没配图时图版是白框、框里的大字母是浅灰，由 `paintBoxes` 与 `domNode` 在画图版和大字母时取，别的主题没有这两个键，落回 `plate` 与 `ink`。**标题颜色怎么认**（`app-title.js`）：标题框自己的颜色是当前墨色加一个**墨色记号**——不透明度 254/255（`markInk`，肉眼看不出；`renderTopCtl`、`rethemeTitle`、`formatTitle` 都会重设，色板变了必须跟着设）。上色仍是内核的一条 `foreColor`（原生撤销、重做照常），「墨色」就是设成标题框这个带记号的颜色。`titleRuns` 里，字上没有自己的颜色、或颜色带记号的是跟墨色走（存 `null`）；其余看色值：等于某个主题强调色的是朱，别的一律是自选色原值——哪怕正好等于某个主题的墨色也不跟主题变（用户 11-20 定）。**为什么要记号**：内核凡是遇到「和继承来的颜色一样」就不写，表格的墨色是纯白，自选纯白会等于没选，给一段字改色时选区外的白也会丢；自选色一律不透明，带记号的墨色在内核眼里是另一个颜色，两者才分得开。不要改成自己动 DOM 落色：那样会绕开原生撤销栈（外部复审 L3-A2、A3 就是这么来的）。
- **按钮的样子**（v00.03.03 L4，真机反馈「按钮要看得出是按钮」）：小按钮 `.tbtn` / `.sbtn` 是直角 1.5px 墨框，看得见的框高 36px，`::after` 把点按区上下各撑出 4px（合计 44px），所以量高度得到的是 36，测点按区要用 `elementFromPoint`；可带 16px 图标。用在顶栏、全屏页的「关闭」、提示行的「版式」「改单词」、入场页的「更多语言」「换一组」、配图面板的「关闭」、「借物与版权」。「单图｜列阵」是相连的两格（`.vbtn`，当前格实心），「完成」实心。配图面板的行（`.prow`）整行带框、高 44。容器按钮让位后屏宽不到 360 时顶栏的图标不显示、只留字（`@media (max-width: 359px)`；346～359 宽带图标会折成两行，实测定的界线）。候选栏、义项栏、标题工具栏按用户 11-20 的决定保留原样。`i-layout`、`i-pen` 两个图标是自己画的，不是 Phosphor。编辑面有 `<main>` 与一个只给读屏的一级标题。配图面板「默认图 · 调整取景」调用 `openCropper(i, "def", state.image, 现在的默认取景)`：第四个参数是从哪份取景接着调，应用后所有没有单独配图的格都用它。
- **入场界面**（v00.02.01 / T18）：没有有效草稿时先到 `#entry`（单词 `#wordInput`、6 个随机预设 `CORE.pickPresets`、填表人 `#fillerCtl`、「开始填充」）；有草稿直接进编辑界面（`focusEntry` 在读完草稿后路由），18h 清理后回入场界面。编辑界面提示行右侧「改单词」（`#toEntry`）回到入场界面（改词页）。改词页（第七批 T30）顶栏「返回｜保存｜主题」：保存走同一套校验，`app.draft.persistNow()` 等这一版真正写进本设备后留在本页、Toast「已保存」，失败或原稿保护阻塞时变「重试保存」并页内说明；返回时无修改直接回，有待应用或未写入的修改（`app.draft.unsavedNow()`）从返回按钮向下展开 `#leavePop`（保存并返回 / 放弃修改 / 继续编辑）；改词页回车 = 保存并返回。输入只暂存在入场页，`submitEntry` / `validateEntry` 统一校验（空单词、屏蔽词就地说明、不复述原词），会清空已有内容的格时先弹 `#wordConfirm`（初始焦点在「保留原单词」），通过后 `applyEntry` 一次性 `setLetters`（`keepSame`）、给字母变了的格递增配图序号并保存。填表人只在入场界面改，卡上只显示（镜像画出）。读草稿期间 `#wordInput` 禁用，预设与主按钮的点击由捕获阶段守卫拦下。

- **草稿**（v00.02.01 / T23 起）：主键 `backronym-draft-v2`，同时写 `setStorage` 和 `localStorage`，读取取较新的一份。旧版两个键 `acronym-draft-v1`、`acronym-draft-v1-bak` **只删不读**：`draft.js` 的 `purge` 每次清理时无条件定向删除，删除失败由 `cleanupFailed` 机制重试，不碰其它键。`CORE.migrateDraft` 只做字段合法性校验（要求 `v: 2`，没有就是坏数据；`keys` 恒为 0），不再转换旧格式。恢复副本键 `backronym-draft-v2-rescue`（两侧都写）存**原文字符串的 JSON 数组，最多 3 份**（`RESCUE_MAX`），同字节去重，每份按自身 `t` + 18h 到期；`preserve` 逐侧「读 → 合并 → 写 → 读回确认含这一份」，读不到某侧现有副本就不写那一侧，已满 3 份未到期就算保全失败、不挤掉任何一份。读到新版原文却套用到界面时出错（或原文结构不能用）时，`app-draft.js` 的 `draftGuard` 闸门在**第一次覆盖主键前**调 `draftStore.preserve(raw)` 把原始字节存进副本、逐侧读回比对，至少一侧一致才放行；两侧都失败就不覆盖、编辑只留内存、底部写明。读取抛错（没拿到原文）时闸门先 `recheck()` 重读主键：读到原文走保全，确认为空或过期才放行，仍失败不写。读到了稿、但主键有一侧读失败（如本地旧 LIFE 可读、端上较新的 LOVE 读不到）时，`read()` 的 `failed` 记下是哪一侧，`app-draft.js` 的 `sideGuard` 让那一侧在核实前不写（`draftStore.write(payload, skip)`，另一侧照常写）；`sideCheck` 用 `recheck(sides)` 只重读那一侧，读到的每份未到期原文（与恢复稿同字节的除外，`sideKeep`）先 `preserve` 再放行并补写，仍读失败或保全失败就继续不覆盖、底部写明。**先保全**：两侧都读到、但某一侧主键存着与恢复稿字节不同的未到期原文时（如跨会话：本地较新的 LIVE、端上较旧的 LOVE），`read()` 的 `differ` 记下那一侧，同样挂 `sideGuard`（`sideRead` 为假，提示不说「读取失败」），覆盖前先把它存进副本。副本从不续期；`read()` 把主键和副本数组里的每一份（两侧）一起比较，取有效且最新；清理逐份剔除到期项，数组空了删键。`readDraft` 先迁移验证再比时间（不合法的一份不能淘汰完整草稿）；读完前 `#wordInput` 与「完成」是禁用的，恢复本身只重绘、不写盘、不刷新时间戳。连续18h无内容更新保存则到期，清当前作品/主稿/副本；无旧稿宽限。底部显示规则、真实保存状态与到期时间。详见 `docs/draft-expiry-assessment.md`。
